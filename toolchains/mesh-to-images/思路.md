这个问题其实可以通过一个比较成熟的几何方法解决，而且不需要反复调整相机位置，也不需要通过渲染结果判断建筑是否被裁切。

对于你的任务，我建议采用：

固定相机方向 + 正交投影（Orthographic）+ 根据建筑包围盒自动计算相机视野范围。

核心思想是：相机角度确定后，将建筑包围盒的 8 个顶点投影到相机平面，计算它们在画面中的最大宽度和高度，再据此设置相机的 `ortho_scale`。

## 1. 为什么推荐正交相机？

Blender 支持两种主要投影方式：

- 透视投影（Perspective）：距离相机越远，物体看起来越小。
- 正交投影（Orthographic）：物体在画面中的大小与距离无关。

对于你的屋顶形态分类，正交投影更适合自动化，因为它没有透视缩放，视野计算也更加直接。

而且，你的目标不是生成具有摄影效果的图片，而是尽可能清楚地展示建筑的三维几何。

## 2. 如何确保建筑完整进入画面？

假设已经得到 OBJ 模型的包围盒中心：

\\[ C=(c_x,c_y,c_z) \\]

以及包围盒的 8 个顶点。

### 第一步：确定相机方向

例如：

- 俯角：45°
- 方位角：30°
- 相机朝向：建筑包围盒中心

在 Blender 中可以使用 `mathutils.Vector` 和 `to_track_quat()`，让相机自动指向中心。

### 第二步：将包围盒顶点转换到相机坐标系

对每个顶点 \\(P_i\\)，计算：

\\[ P_i^{cam}=R^{-1}(P_i-C) \\]

其中 \\(R\\) 表示相机旋转矩阵。

这样就能得到每个顶点在相机坐标系中的位置：

\\[ P_i^{cam}=(x_i,y_i,z_i) \\]

对于正交投影，画面中的水平和竖直方向分别对应相机坐标系的 \\(x_i\\) 和 \\(y_i\\)。

### 第三步：计算建筑在画面中的投影尺寸

\\[ W=\max(x_i)-\min(x_i) \\]

\\[ H=\max(y_i)-\min(y_i) \\]

这两个值就是建筑在当前观察方向下的投影宽度和高度。

### 第四步：自动设置正交相机尺度

在 Blender 中，`camera.data.ortho_scale` 对应相机视野的竖直尺寸（对于常见的横向或正方形输出）。

如果图像宽高比为：

\\[ a=\frac{\text{image width}}{\text{image height}} \\]

那么为了完整容纳建筑，需要满足：

\\[ \text{ortho\\\_scale}\geq H \\]

以及：

\\[ a\cdot\text{ortho\\\_scale}\geq W \\]

因此：

\\[ \boxed{\text{ortho\\\_scale}=\max\left(H,\frac{W}{a}\right)\times m} \\]

其中 \\(m\\) 是留白系数，例如 `1.1`，表示在建筑周围留出约 10% 的额外空间。

对于你计划使用的 `512 × 512` 图片：

\\[ a=1 \\]

所以可以简化为：

\\[ \boxed{\text{ortho\\\_scale}=\max(W,H)\times1.1} \\]

这样，无论建筑是狭长形、三角形还是不规则多边形，都能自动完整进入画面。

## 3. Blender 中如何实现？

核心代码其实很短：

```
from mathutils import Vector# 获取建筑包围盒的8个顶点（世界坐标）corners = [    obj.matrix_world @ Vector(corner)    for corner in obj.bound_box]# 包围盒中心center = sum(corners, Vector()) / 8# 相机已经设置好方向并指向 centercamera.location = center + camera_offsetdirection = center - camera.locationcamera.rotation_euler = direction.to_track_quat('-Z', 'Y').to_euler()# 将包围盒顶点转换到相机局部坐标系rotation_inv = camera.rotation_euler.to_matrix().inverted()projected = [    rotation_inv @ (p - center)    for p in corners]# 投影宽度和高度width = max(p.x for p in projected) - min(p.x for p in projected)height = max(p.y for p in projected) - min(p.y for p in projected)# 图像宽高比aspect = 1.0  # 512 × 512# 自动调整正交尺度camera.data.type = 'ORTHO'camera.data.ortho_scale = max(height, width / aspect) * 1.1
```

这段代码展示了核心计算过程，假定 `obj` 是建筑模型对象、`camera` 是相机、`camera_offset` 已根据方位角和俯角计算好。

如果一个建筑 OBJ 包含多个 Mesh 对象，需要收集全部 Mesh 对象的包围盒顶点，而不能只使用其中一个对象。

另外，这段代码还有一个可以进一步优化的地方：它默认相机瞄准包围盒中心，但对于形状很不规则的建筑，投影范围的中心可能不完全对应包围盒中心。

为了让建筑在图片中真正居中，可以计算：

\\[ x\_{mid}=\frac{\max(x_i)+\min(x_i)}{2} \\]

\\[ y\_{mid}=\frac{\max(y_i)+\min(y_i)}{2} \\]

然后沿相机局部 X、Y 方向微调相机位置，使投影中心与画面中心重合。

## 4. 相机距离是否也需要计算？

对于正交相机，距离不会影响建筑在画面中的大小。

因此，你可以将相机放在距离建筑中心足够远的位置，例如建筑包围盒对角线长度的 2 倍。

但需要保证：

- 相机位于建筑外部；
- 建筑所有顶点都在相机前方；
- `clip_end` 足够大，避免远裁剪面截断建筑。

所以在正交投影方案中，相机距离只是确保正确渲染的辅助参数，真正控制画面大小的是 `ortho_scale`。

## 5. 对 City4RPV 的实际建议

我建议你最终将相机参数设计成：

```
render_building(    obj_path="building.obj",    output_path="top.png",    azimuth=0,    elevation=90,    resolution=(512, 512),    margin=1.1)
```

每栋建筑自动执行：

1. 读取 OBJ，计算完整包围盒。
2. 根据方位角和俯角确定相机方向。
3. 将包围盒投影到相机平面。
4. 计算 `ortho_scale`，自动适配画面。
5. 渲染 PNG。

这套方法最重要的优点是确定性：只要模型坐标、相机方向和包围盒正确，就可以在渲染之前通过数学计算确保建筑完整进入画面。

对于你未来可能处理的十几万栋建筑，这比通过图像检测或不断试探相机位置来调整画面更加可靠。
